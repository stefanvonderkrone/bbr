From orchestration by convention to atomic Presentation transitions

The proposed seam does not cancel everything when a Session changes. It separates ephemeral, Session-bound projections from durable work that must finish against the Pull Request that authorized it.

Critical transition

Replacing a Session

A replacement includes the Session, persisted Pending Review, initial Buffer, navigation, and Session-relative UI state. Reviewer preferences such as layout and scope survive.

Current ordering

Mutation happens before validation finishes

  1. Destroy the old Session.
  2. Set current = new_session.
  3. Clear folds, isolation, in-flight markers, and submission UI.
  4. Load Pending Review; silently substitute empty on failure.
  5. Build Buffer; on failure retain the old Buffer value—a potentially dangling hybrid.

Proposed transaction

Preparation is private; publication is atomic

  1. Own the candidate Session without touching published state.
  2. Load its Pending Review; failure discards the candidate.
  3. Build its Buffer and normalized navigation in staging.
  4. Commit the complete candidate as the new published state.
  5. Destroy the replaced state only after the commit is valid.
