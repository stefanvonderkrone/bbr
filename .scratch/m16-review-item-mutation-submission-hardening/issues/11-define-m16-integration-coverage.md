# Define M16's deterministic integration coverage

Type: grilling
Status: resolved
Blocked by: 02, 05, 06, 07, 08, 09, 10, 15

## Question

What deterministic Action, typed-command/completion, allocation-failure, persistence-failure, Session Epoch, Submission recovery, Retry-After, terminal suspend/restore, and vaxis shift-selection sequences must cross the Presentation seam, and which narrow PTY or credential-gated live checks remain necessary because fakes cannot establish their behavior?

## Answer

Use layered deterministic coverage. Test each rule exhaustively at the lowest seam that owns it, then drive one representative `Action -> OwnedCommand -> typed completion -> Projection` sequence through Presentation for each cross-module invariant. Do not repeat every lower-level branch through Presentation. The seam-crossing suite proves composition, identity, persistence ordering, rollback, command correlation, stale-result admission, and visible projection without creating a Cartesian product of Draft kinds, Anchor shapes, failure classes, and Session states.

The Draft-mutation Presentation sequences must prove: a prefilled edit preserves TempId and parentage through stage-persist-publish; a real edit or re-anchor resets `failed` while an identical result is a no-op; root re-anchor publishes the replacement CommentScope and ScopeProjection while retaining identity-based navigation; confirmed deletion atomically removes the selected Draft subtree; an active or recovered SubmissionRun refuses every mutation; ambiguity link, confirm-unpublished, decide-later, and Abandon recovery produce their settled mutability; LocalReview replaces AnchorSnapshot while Remote review keeps Bitbucket Reconciliation boundaries; and Session replacement reloads the accepted persisted mutation. Comment, Reply, Suggestion, side/range, 30-line, fence, graph-closure, and immutable-subtree branch tables remain exhaustive in Review, Composer, Anchor/Selection, and PendingReviewStore tests rather than being duplicated in every Presentation sequence.

Published Comment mutation must cross Presentation with one author-owned edit and one confirmed delete: ActionAvailability uses UUID ownership, the typed command carries Repository-qualified PullRequest identity plus CommentId, definitive failure restores the initiating interaction, response-lost completion starts Reconciliation without retry, success starts Reconciliation without optimistic graph mutation, and completion after Session replacement produces the settled PullRequest-qualified result. Deterministic Bitbucket adapter fixtures separately cover body-only request shape, Suggestions as ordinary `content.raw`, Deleted Comment decoding, every ApiError class, missing identity evidence, and immutable published Anchors.

Submission coverage must drive the dependency-tree Overlay from authorization to terminal result. Representative sequences must prove parent-before-Reply commands, per-item checkpoint-before-next-POST, continue/skip/abort behavior, selected-subtree retry without unrelated roots, static waiting and exhaustion detail, and terminal clean versus partial projection. A rate-limited POST must carry `retry_after_ms` through the typed completion, persist its wait checkpoint before a wait command, survive wait-command launch failure, resume, and emit the next POST only after the correlated completion. A separate ambiguous-POST sequence must exercise the independent Duplicate-guard budget and end in `outcome_unknown` when publication cannot be established. Lower seams exhaustively cover both `Retry-After` wire forms, case-insensitive lookup, malformed/expired/overflow fallback, `429`/`5xx` propagation, ignored metadata for other classes, `max` in both directions, exact 1s/2s waits, three-attempt ceilings, terminal-delay carryover, and POST versus Duplicate-guard budget independence.

Recovery and stale-SourceCommit coverage must cross Presentation with: interrupted-run discovery and explicit claim; held-lock refusal; current-source resume; changed-source read-only Duplicate guard with matched, missing, failed, and unresolved outcomes; automatic clean completion versus explicit terminal-partial Abandon recovery; and immutable ambiguous evidence. The Stale repair gate must prove that initial preflight creates no SubmissionRun and emits no POST, reload publishes one complete Candidate Session or preserves the exact old Session and Session Epoch on failure, each root's settled repair eligibility controls only its own subtree, unrelated stale roots are excluded, and a second SourceCommit change refuses the fresh run before POST.

Session-bound and Durable Operation work must be interleaved deliberately. Replace the Session while Draft POST, wait, Reconciliation, External Edit, and File Enrichment completions are outstanding. Verify that Session Epoch rejects stale Session-bound work, a failed replacement keeps the old Epoch and accepts its valid work, and OperationId plus Repository-qualified PullRequest identity lets Submission and published Comment mutation continue without changing the wrong Session. Include late, duplicate, wrong-OperationId, wrong-TempId, and command-launch-failure completions at least once per distinct admission rule, not once per product scenario.

External Edit must use the same boundary. Presentation tests start `Ctrl-E` in the Composer Interaction Context, inspect the owned correlated command and exact body snapshot, refuse Composer input while it is pending, reject a stale or mismatched completion, atomically seed accepted changed bytes, retain the original body on allocation failure, and keep the Composer open with each settled footer outcome. Adapter tests exhaustively cover editor precedence, safe shell argument passing, secure directory and `0600` file creation, exact bytes, UTF-8/NUL/size validation, process outcomes, cleanup, and fatal restoration failure without requiring a terminal.

Selection tests must keep the three layers separate. Pure Keymap and Presentation tests feed portable Shift+Arrow strokes and verify `select_up`/`select_down`, Selection start, extension, contraction, reversal, refusal shapes, and `Esc`. Pinned-vaxis adapter fixtures feed known escape sequences and verify the resulting key plus Shift modifier. A generic PTY cannot prove what a terminal emulator or multiplexer sends, so real Shift+Arrow compatibility remains a documented manual check. M16 does not define a supported-terminal list: `v` remains the reliable Selection Action, while Shift+Arrow remains terminal-dependent compatibility evidence.

Failure injection follows observable contracts. Run exhaustive allocation-failure sweeps for each distinct stage-persist-publish transition. Script one failure for every transaction-shaped PendingReviewStore intention and every new typed-command launch path. After each failure, compare the complete observable Projection, retained Composer/re-anchor/confirmation interaction, Buffer, navigation, durable records, command queue, and eventual cleanup. Do not assert private arena positions, ArenaRing generations, allocator call numbers, or private Submission phases: those are implementation details, and safe refactors may change them without changing the contract.

Add a deterministic terminal-adapter harness below the vaxis loop. It drains each typed command family into a scripted executor, returns the completion through the same sink, and proves ownership transfer, correlation, queued completion, launch failure, event admission, and reaping with no real network, sleep, terminal, or PTY. Presentation sequences use this harness where the async glue itself is under test; ordinary policy tests dispatch completions directly.

Keep non-hermetic checks explicit and outside `zig build test`. One opt-in PTY External Edit smoke uses a controlled helper program to verify inherited terminal streams, cooked mode and echo during handoff, exact prefilled/returned bytes, mouse disable/restore, alternate-screen exit/re-entry, complete redraw, and a working recreated input loop. Signals and other failure branches stay deterministic below it. Manual Shift+Arrow checks record terminal, version, multiplexer, and configuration but create no support guarantee.

Add one credential-gated, mutation-opt-in Bitbucket check for a disposable PullRequest. It acquires the authenticated UUID, creates a uniquely marked Review-level Comment, re-fetches and verifies identity/body/author/CommentScope, updates only `content.raw`, re-fetches and verifies stable identity and scope, deletes, and re-fetches to verify absence or the documented Deleted Comment shape. It performs best-effort cleanup on every failure, prints no Credential material, and requires an explicit destructive opt-in such as `BBR_ALLOW_LIVE_MUTATION=1`. Do not require a live `429`: Bitbucket cannot be made to return it reliably, so raw-response fixtures and deterministic parser/policy tests establish `Retry-After` behavior.
