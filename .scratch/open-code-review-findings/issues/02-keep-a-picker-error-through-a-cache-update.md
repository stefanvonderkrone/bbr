# Keep a Picker error through a cache update

Status: ready-for-agent
Blocked by: none

## Problem

Commit `e60b43c0` stopped a File Enrichment build from clearing an unrelated action error, such as an unread `picker_load_failed`. An enrichment build now clears only an error that `setByFileEnrichment` names.

The success path of a Buffer build in `src/tui/presentation.zig` still has this branch:

```zig
if (job.kind != .enrichment) {
    self.action_error = null;
} else if (!EnrichedFile.allSpeculative(job.enrichments.items)) {
```

A `.cache_update` build takes the first branch. A cache update also runs beside other work, because a lease release or a focus check queues it. So a cache update that completes while `picker_load_failed` shows can clear that message before the user reads it.

Triage verified this finding with a test. The test is in the brief below. The `ocr-review` control review of `e60b43c0` reported it. Ticket [02 of the Open Code Review evaluation](../../open-code-review/issues/02-evaluate-the-review-rules-on-ten-bug-fixes.md) records the run.

## Proposal

- Write a test that shows `picker_load_failed`, completes a `.cache_update` build, and expects the message to stay.
- If the test fails, decide which build kinds the user starts and which run in the background. Only a build that the user starts can clear an unrelated action error.

## Acceptance criteria

- [ ] A test decides whether a completed cache update clears `picker_load_failed`.
- [ ] If the message is cleared, a background build no longer clears an unrelated action error, and the test passes.
- [ ] `zig build test` passes.

## Agent Brief

**Category:** bug
**Summary:** A completed cache update must not clear an unrelated action error, such as `picker_load_failed`.

**Current behavior:**
When a Buffer build of any kind other than `.enrichment` succeeds, Presentation sets `action_error` to `null`. A `.cache_update` build runs in the background, because a lease release or the focus check queues it. So a cache update that completes while `picker_load_failed` shows clears the message before the user reads it.

Triage reproduced it in the Review recovery suite (`zig build test-review-recovery`). The test fails with `expected .picker_load_failed, found .action_refused`, which means that `action_error` is `null`:

```zig
test "Review recovery Picker error survives a completed cache update" {
    var store = bbr.review.InMemoryStore.init(testing.allocator);
    defer store.deinit();
    var state = try Presentation.init(testing.allocator, .{ .reviews = store.store() }, .{
        .initial = .{ .key = try OwnedReviewIdentity.init("workspace", "repo", 1), .session = try testSession(testing.allocator, 1, 'a') },
    });
    defer state.deinit();
    try state.dispatch(.{ .key = .{ .codepoint = 'p', .text = "p" } });
    const list = state.takeCommand().?.list_pull_requests;
    try state.dispatch(.{ .pull_requests_loaded = .{
        .command_id = list.command_id,
        .work_id = list.work_id,
        .outcome = .{ .failed = bbr.diagnostic.Failure.capture(.picker_list, .execute, .{}, .{ .zig = error.ServerError }, @src()) },
    } });
    try testing.expectEqual(ActionError.picker_load_failed, state.projection().action_error.?);
    const published = state.published.?;
    try state.queueCacheBuild(published, published.session.enrichment.focused);
    try completeDisclosureBuild(&state);
    try testing.expectEqual(ActionError.picker_load_failed, state.projection().action_error orelse .action_refused);
}
```

The test queues the cache update through `queueCacheBuild`. In the app, `stageReleasedSearchLeases` or `ensureFocusedEnrichment` queues it through the same function.

**Desired behavior:**
- A successful `.cache_update` build clears only an action error that the cache update path can set. The File Enrichment fix in `e60b43c0` uses `setByFileEnrichment` for the same rule.
- Every other build kind keeps its current reset.

**Key interfaces:**
- `DisclosureBuild.Kind.cache_update`: the build kind that changes.
- The success reset of `action_error` in the acceptance of a Buffer build.
- `setByFileEnrichment(ActionError) bool`: the pattern to follow.

**Acceptance criteria:**
- [ ] The test above, or a test with the same steps, is in the Review recovery suite and passes.
- [ ] The test "Review recovery Picker error survives an unrelated File Enrichment completion" still passes.
- [ ] A completed cache update still clears an error that the cache update path sets. A test shows this.
- [ ] `zig build test` passes.
- [ ] `zig fmt --check src build.zig tests` passes.

**Out of scope:**
- `.draft_save` and `.draft_mutation` builds. They can also finish after the user moves on, but triage did not verify a defect for them. File a new ticket if a test shows one.
- A change to which action errors the File Enrichment path clears.
